# バッチ設計ビューワー

目的は、現行バッチが「何を読み、どう処理し、何を書くか」を、人が設計書の順に読める形で示すこと。ソースから機械的に取れる事実（入出力文、レイアウト、DD）はスクリプトで抽出し、業務上の意味づけ（名前、説明、処理のまとまり、例外の意味）はモデルに書く。2つを分けておくと、ソースが変わったときに事実だけを取り直せる。

## 読む順番（＝作る順番）

人が理解しやすい順に、解析も画面も並べる。詳しくは [reading-order.md](references/reading-order.md)。

1. 範囲と前提：版・ファイル・依存（COPY、JCL、PROC）を固定し、未入手のものを記録する。
2. 入出力：ジョブとステップ、DD とデータセット。
3. データ：データストアとキー、データ項目（意味でまとめる）。
4. 骨格：メインループと、1件の正常な流れ。
5. 例外：EOF、未登録、I/O エラー、異常終了。
6. 定型処理：同じ形の段落はまとめ、違いだけを表にする。
7. 細部と網羅：全行の分類、未解析の行、未確認事項。

## 2種類のビューワー

| 種類 | 入力 | 画面 |
|---|---|---|
| プログラムビューワー | `*.program.json`（[program-model.md](references/program-model.md)） | 概要と合意事項、ジョブフロー、DFD、DB・ファイル一覧、データ項目定義、処理フロー、例外、処理パターン、網羅 |
| ジョブビューワー | `*.job.json`（[job-model.md](references/job-model.md)） | 概要、ジョブフロー、DFD（ジョブ全体）、DB・ファイル一覧、CRUD図、データ項目定義、網羅と未確認 |

ジョブビューワーは、データセットを DD 名ではなく DSN で同一視し、ステップをまたいで1つのデータストアにまとめる。ステップからプログラムビューワーへリンクできる。

## 手順

1. 原本・COPY句・JCL・PROC をプロジェクト内に置き、取得元とコミット、ライセンスを記録する。
2. 事実を確認する。`python -X utf8 scripts/extract_cobol.py PGM.cbl --copybooks CPYDIR` と `python -X utf8 scripts/extract_jcl.py JOB.jcl --procs PROCDIR` で、SELECT・レイアウト・入出力文・CRUD・DD を見る。`unsupported` が空でなければ、その構文を手で確認する。
3. データ辞書（`dictionary.json`）に、COBOL項目名 → データ項目名（日本語）を書く。意味が同じものは同じ名前にし、違うものは名前を分ける（例：口座の有効状態／カードの有効状態）。辞書は複数のビューワーで共有する。
4. モデルを書く。プログラムは処理フロー（レーンと行）、DFD、例外、処理パターン、未確認事項を書く。ジョブはステップの並びと、JCL の無いステップの仮定、ユーティリティの入出力、データセット名を書く。
5. 組み立てる。`python -X utf8 scripts/build_viewer.py program MODEL.program.json --out OUT.html`（ジョブは `job`）。モデルが存在しないID・項目・行を参照していたら、何も書き出さずに止まる。
6. 確かめる。`node scripts/smoke_test.js OUT.html ...` で全画面・つながりのリンク・幅400pxの横はみ出しを確認する。そのうえで、代表的な箱・マス・項目を実際に押し、根拠のコードと行番号が正しいかを目で確かめる。

## 守ること

- 抽出は簡易解析であり、完全なCOBOL構文解析器ではない。項目単位のCRUDは名前の参照と代入先からの推定で、画面にもそう書く。
- 仮定は仮定として残す。JCL の無いステップ、推定した DSN、未入手の制御文は、モデルの `assumed`・`utilityNote`・`openItems` に書き、画面で破線や「推定」の表示になるようにする。
- 原本の不整合（表示メッセージの食い違いなど）を黙って直さない。例外の一覧や定型処理の表に事実として載せる。
- 図に載ったこと、リンクがつながったことを、意味まで確認できたことと同じ扱いにしない。網羅の画面は漏れの点検のためにある。
- 設計書の様式は、IPA『機能要件の合意形成ガイド』（バッチ編を含む）など一般的なバッチ設計書の構成を参考にしている。ガイド本文の章立てと1対1で対応させたものではない。
