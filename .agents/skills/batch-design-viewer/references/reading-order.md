# 解析の順番と画面の対応

人が理解しやすい順は「目的 → データ → 骨格 → 1件の流れ → 例外 → 定型処理 → 細部」。行番号順に読むと OPEN／CLOSE のような定型処理が前半を占め、本筋が見えにくくなるため、この順に解析し、画面もこの順に並べる。

漏れを防ぐための棚卸し（段落・判定・入出力文・DD の一覧）は、最初にスクリプトで機械的に済ませてよい。棚卸しは「裏の台帳」、画面の順番は「説明のストーリー」として分ける。

| 順 | 解析すること | 問い | 画面 | 設計書でいうと |
|---|---|---|---|---|
| 0 | 範囲と前提 | どの版を、どこまで見るか | 網羅と未確認 | レビュー記録・課題一覧 |
| 1 | ジョブの入出力 | 何を読み、何を出すバッチか | 概要、ジョブフロー | バッチ処理一覧、ジョブフロー図 |
| 2 | データの流れ | データはどこから来て、どこへ行くか | DFD | DFD |
| 3 | データストアとキー | 何を何で照合・更新するか | DB・ファイル一覧、CRUD図 | DB一覧・ファイル一覧、CRUD図 |
| 4 | データ項目 | 同じ情報がどこにあり、どこで使われるか | データ項目定義 | データ項目定義書（項目辞書） |
| 5 | 処理の骨格 | 全体はどんな順で動くか | 処理フロー | 処理フロー（流れ図） |
| 6 | 例外 | 失敗や終端で、どこへ進むか | 例外と異常系 | エラー処理一覧・メッセージ一覧 |
| 7 | たどって確かめる | 図の通りに動くか | 処理パターン | テストケース・処理シナリオ |

## 図の決まり

- 処理フローは JIS X 0121 の記号に合わせる（端子、処理、判断、定義済み処理＝別段落の呼出し）。
- 正常系は main レーンに縦一列で置き、例外は right（エラー・未登録）、EOF のように正常な終わり方の分岐は left に置く。
- 同じ形の段落（OPEN／CLOSE など）は1つの箱にまとめ、`routines` の表で違いだけを示す。違いのある行は `diffRows` で強調する。
- 名前は業務の言葉を主にし、元の段落名やDD名を添える。
- 直感に反する動作は、図に注記（`notes`）として書く。
- DFD では開閉などの制御を扱わない。データの流れだけを描く。
- 網羅の確認は図ではなく、全行を並べた帯と一覧で行う。

## 共通ID

| ID | 意味 | 例 |
|---|---|---|
| S | ジョブのステップ | S2 日次取引の計上 |
| P | プログラム内のDFDのプロセス | P2 カードを照合する |
| F | データフロー | F4 口座ID |
| E | 外部 | E1 前工程 |
| D | データストア（DB・ファイル・データセット） | D5 口座マスター |
| DI | データ項目（意味の単位） | DI-02 カード番号 |

どの画面でも、詳細欄の「つながり」に同じ形でIDを並べ、押すと該当する画面と要素へ移る。
